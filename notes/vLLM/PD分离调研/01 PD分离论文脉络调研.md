# 01 PD分离论文脉络调研

本文沉淀 PD 分离方向的论文调研结果，按时间线梳理每个阶段的核心论文、它们解决的问题与架构设计，为后续 vLLM 代码演进调研提供理论对照。

## 1 问题起源：Prefill 与 Decode 的相位差异

PD 分离的理论基础是 LLM 推理两个阶段截然不同的资源画像，这个观察在多篇论文中被独立验证：

| 维度 | Prefill（预填充） | Decode（解码） |
| --- | --- | --- |
| 计算特征 | 计算密集（compute-bound），一次处理全部输入 token，矩阵乘规模大 | 访存密集（memory-bound），每步只算一个 token，却要读全量 KV cache |
| GPU 利用率 | 算力利用率高 | 算力利用率极低（通常个位数百分比），带宽利用率高 |
| 延迟语义 | TTFT（time to first token） | TPOT / ITL（每 token 延迟） |
| 批处理行为 | 时长随 prompt 长度剧烈波动，是干扰源 | 时长稳定，是被干扰方 |

混合部署（colocated serving）下两者互相干扰：一个大 prompt 的 prefill 会阻塞同 batch 内所有 decode 请求的逐 token 生成，造成 ITL 尖刺；同时两阶段被迫共享同一套并行策略（TP/PP）与资源配置，无法独立优化。这是所有 PD 分离工作的共同出发点。

### 1.1 前置奠基工作

- **PagedAttention / vLLM**（Kwon et al., SOSP 2023）：KV cache 分页管理，使 KV 变成可按 block 寻址、可搬运的离散结构；这是后来一切跨实例 KV 传输的物理基础；
- **Sarathi**（Agrawal et al., arXiv 2308.16369）：提出 chunked prefill，把 prefill 切成小 chunk 与 decode 拼 batch（stall-free batching）；这是 PD 分离的**替代路线**，两者长期并存竞争，理解 chunked prefill 的局限（chunk size 难调、prefill 算力仍被 decode 稀释）才能理解为什么要走分离路线；
- **Pope et al.**（OSDI 2022, Efficiently Scaling Transformer Inference）：最早系统性刻画 prefill/decode 双相位的算力-带宽画像，并提出流水线式拆分思想。

## 2 第一阶段：概念提出与可行性证明（2023.11 – 2024.01）

三篇几乎同期出现的论文从不同角度提出并验证了 PD 分离。

### 2.1 Splitwise（Microsoft，ISCA 2024，arXiv 2311.18677）

**定位**：从数据中心硬件经济学出发，论证按相位拆分机器可以用更便宜/更省电的硬件跑 decode。

**核心架构设计**：

1. **Phase splitting**：prompt 计算机器（prompt machines）与 token 生成机器（token machines）物理分离，请求先在前者完成 prefill，再把状态迁移到后者继续 decode；
2. **状态迁移**：迁移对象为 KV cache（论文实测 KV 传输代价在 InfiniBand 互连下可以忽略或很好地被掩盖）；采用**layer-wise 传输**——每算完一层就立即发送该层 KV，让网络传输与后续层的计算 overlap；
3. **异构硬件混布**：decode 不依赖最新 GPU 的算力，可用旧卡/低功耗卡；论文按 throughput、cost、power 三个目标设计集群配比，报告 1.4x 吞吐 + 20% 成本下降，或同成本功耗下 2.35x 吞吐。

**历史意义**：首次把 PD 分离从调度技巧上升为集群架构设计问题，确立了「KV 传输是分离架构唯一新增成本，且可被高速互连消化」这一关键论断。

### 2.2 DistServe（PKU/UCSD 等，OSDI 2024，arXiv 2401.09670）

**定位**：第一个系统化的 PD 分离 serving 系统，目标函数是 **goodput**（同时满足 TTFT 与 TPOT SLO 的最大请求速率）。

**核心架构设计**：

1. **双实例分离**：prefill 与 decode 跑在不同 GPU 上，prefill 完成后通过高速互连传输 KV cache，彻底消除相位干扰；
2. **解耦的并行策略**：两个阶段独立选择 TP/PP 配置——prefill 计算密集适合大 TP，decode 访存密集适合不同的并行形态；
3. **Placement 算法**：搜索 P:D GPU 配比与并行度组合，按集群带宽约束放置两阶段以最小化 KV 传输开销（同机 NVLink > 跨机 IB > 以太网），离线枚举评估每种配置的 goodput 后选优；
4. **调度**：prefill 侧优化 TTFT，decode 侧优化 TPOT，各自独立 batch。

**结果**：相比当时 SOTA（vLLM 等）在满足 SLO 前提下服务 7.4x 更多请求或承受 12.6x 更紧的 SLO。

**历史意义**：定义了 PD 分离的标准系统形态（P 实例 + D 实例 + KV 传输 + 独立并行策略），后续几乎所有工程实现（包括 vLLM 的 disagg 模式）都是这个形态的直接映射；也明确了 PD 分离不提升单机吞吐、只改善 SLO goodput 的定位。

### 2.3 TetriInfer（ICT/中科院等，arXiv 2401.11181）

**定位**：面向混合下游工作负载的 PD 分离，关注多个下游任务共享 GPU 池时的干扰问题。

**核心架构设计**：

1. 同样拆分 prefill/decode GPU 组，但引入**块级（chunk）粒度**：prompt 切分为固定大小 chunk，使 prefill GPU 尽量保持计算饱和，不同请求的 chunk 可以流水拼接；
2. 面向混合负载的调度编排，避免不同下游任务的 prefill/decode 互相干扰。

**历史意义**：chunk 级 KV 迁移的思想后来在多个系统的流水线传输设计中重现。

## 3 第二阶段：从学术系统走向生产架构（2024 年中 – 2024 年末）

### 3.1 Mooncake（Moonshot AI + 清华，FAST 2025，arXiv 2407.00079）

**定位**：Kimi 的生产级 serving 平台，是 PD 分离从论文走向大规模生产的标志性系统。核心思想从「相位分离」升级为 **KVCache-centric**：KV cache 不再是请求的附属状态，而是与计算解耦的一等公民。

**核心架构设计**：

1. **三层分离**：
   - **Prefill 池 / Decode 池**：计算与相位绑定，各自独立扩缩容；
   - **KVCache 池（disaggregated cache）**：利用 GPU 集群中闲置的 CPU DRAM 和 SSD 构成分层 KV 缓存池，KV 可以跨请求、跨实例复用（前缀缓存从实例本地升级为全局资源）；
2. **Conductor 调度器**：KVCache-centric 全局调度，平衡最大化有效吞吐与满足延迟 SLO；调度时优先考虑 KV cache 局部性（把请求发给已有前缀缓存的节点），在过载场景下用基于预测的 **early rejection** 提前拒绝注定无法满足 SLO 的请求；
3. **Transfer Engine**：独立的高性能 KV 传输组件，拓扑感知地选择传输路径（RDMA/TCP），分块流水线传输，后来开源为 Mooncake Transfer Engine，并成为 vLLM/LMCache 等的传输后端之一；
4. **chunk 级 prefill**：prefill 内部采用分块流水线，与传输 overlap。

**结果**：长上下文场景吞吐提升最高 525%（仿真），真实负载下 Kimi 多承接 75% 请求。

**历史意义**：确立了 PD 分离的完整生产形态 = 分离计算池 + 全局 KV 池 + KV-aware 调度 + 高性能传输引擎；KV cache 复用（prefix cache）与 PD 分离从此绑定在一起演进。

### 3.2 同期生产化工作

- **P/D-Serve**（arXiv 2408.08147）：大规模 PD 分离 serving 的工程实践，研究 P/D 配比与自适应；
- **KVDirect**（arXiv 2501.14743）：面向异构 GPU 池的 P/D 分离，KV 直接传输优化；
- **MemServe**（华为）：提出统一 MemPool 与全局 cache，强调 P/D 实例间与多实例间的 KV 共享，是 KVCache-centric 路线的另一分支；
- **DynamoLLM**（Microsoft，arXiv 2408.00741）：集群级动态重组，在 PD 分离框架下按负载动态调整副本数、并行度与请求路由，兼顾性能与能效。

## 4 第三阶段：数据平面标准化与 Agentic 时代（2025 年起）

### 4.1 新负载带来的新压力

2025 年 reasoning model（长 CoT）与 agentic 工作负载（多轮共享长前缀、KV 重用率极高）爆发，PD 分离的关注点从「消除干扰」扩展到：

1. **KV 传输吞吐**：长上下文使单次迁移的 KV 量达到 GB 级，传输成为 TTFT 的主导项；
2. **KV 重用**：agent 场景下同一前缀被反复加载，全局 KV cache 命中率成为核心指标；
3. **异构与弹性**：P/D 异构 TP、异构 GPU 型号、动态角色切换（实例在 P/D 之间漂移）。

### 4.2 NVIDIA NIXL 与 Dynamo

- **NIXL**（NVIDIA Inference Xfer Library）：专门的 KV/张量传输数据平面库，统一抽象 GPU/CPU/文件等多种内存类型上的读写传输，底层可插多种 backend（UCX、GDS、RDMA verb 等）；成为 vLLM、SGLang、TensorRT-LLM 等引擎共享的传输事实标准之一；
- **Dynamo**（GTC 2025 发布）：以 PD 分离为核心的一等架构的分布式推理框架，组件包括 **Smart Router**（KV cache hit rate + 负载感知的请求路由）、**GPU Planner**（动态 P:D 配比）、**KV Cache Manager**（跨节点 KV 块管理）与基于 NIXL 的数据面，支持 vLLM/SGLang/TensorRT-LLM 作为引擎后端；
- **DeepSeek 生产实践**（DeepSeek-V3 技术报告及推理优化报告，arXiv 2501.12948 等）：大规模部署 PD 分离，prefill 使用更大 TP（如 4 节点 TP），decode 使用不同 DP/TP 组合，KV 传输依赖 NVLink + InfiniBand + 自研 3FS 文件系统，是 PD 分离在万卡级生产的公开样本。

### 4.3 SLO 细分与更细粒度拆分

- **Helix**（Microsoft，SOSP 2025）：面向多 SLO 场景的分离 serving，研究如何在多个 SLO 等级间公平高效地共享分离后的资源；
- **LayerServe**：把拆分粒度从「相位」进一步细化到「层」，不同层跑在不同 GPU 组，是 PD 分离思想的广义化；
- **DistAttention / DistServe 后续工作**：decode 内部的 attention 计算也可再拆分（如把 KV 密集的 attention 下沉到辅助节点），代表分离思想仍在继续细化。

## 5 论文视角下的 PD 分离设计要素总结

综合全部论文，一个 PD 分离架构的设计空间可以归纳为五个正交维度，后续 vLLM 代码调研将逐一对应：

1. **拆分粒度**：请求级（整段 KV 一次迁移，DistServe 初期）→ chunk/layer 级流水线（Splitwise、TetriInfer、Mooncake）；
2. **KV 传输路径**：D 拉取（pull/READ）vs P 推送（push/WRITE）；同步阻塞 vs 异步后台；传输介质 NVLink/RDMA/TCP/存储；
3. **KV 的生命周期**：随请求销毁 vs 沉淀为全局 KV 池（Mooncake/LMCache 路线）供前缀复用；
4. **调度与路由**：P:D 配比、并行策略解耦、KV-locality 感知路由、过载拒绝；
5. **可靠性**：传输失败回退本地重算、节点故障后 KV 租约回收、P/D 实例崩溃时的请求恢复。

## 6 待补充问题（留给后续调研）

2. 社区对 pull vs push 模式的争论与选型依据；
3. KV 传输与 prefix caching、speculative decoding、hybrid 模型（MLA/Mamba）兼容性的工程挑战；
4. proxy/router 层（两腿请求编排、kv_transfer_params 传递协议）的标准化过程。
